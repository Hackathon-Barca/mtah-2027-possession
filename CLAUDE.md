# CLAUDE.md

Team **NoLook**'s entry to More than a Hack 2027, Phase 1: label every frame of one match with the team in possession. The challenge rules in `docs/challenge/` are authoritative, and `evaluation/possession_metrics.py` is the specification of the score.

## Match data stays on the team's machines (permanent rule)

The terms of use forbid sending the match data, or any extract of it, to a hosted LLM, and that includes this agent. The video, tracking (ATD), Smart Tagging and homography live in `data/` or under `$MTAH_DATA_DIR`.

- You write and review **code**; a teammate runs it locally.
- What comes back to you is **aggregate only**: scores, possession counts, durations, row counts, validator messages, error tracebacks with the data values stripped.
- Never open, print, `head`, plot-to-image or otherwise read files under `data/` or `$MTAH_DATA_DIR`, and never ask a teammate to paste rows from them. When a script needs inspecting, design it to print aggregates.

## The repository will be public

The submission repository becomes public before the deadline, so every commit is assumed public:

- `data/` and frame-level exports of tracking, tagging or video stay out of git; `.gitignore` already covers `data/`.
- Submissions are generated by an algorithm, never labelled or corrected by hand.
- One documented command regenerates `NoLook.csv` byte for byte from the data bundle.

## Working conventions

- Code, docs and commits are in **English**. Planning issues are in Portuguese.
- Use the terms in `GLOSSARY.md`; when a new domain word appears, settle it there.
- `evaluation/`, `starter/` and `games.py` are vendored from [metrica-sports/more-than-a-hack-2027](https://github.com/metrica-sports/more-than-a-hack-2027). Keep `evaluation/` byte-identical to upstream so local scores match the official scorer.
- Run `python evaluation/validate_submission.py <file>` on the exact file before it is submitted.
- The public window checks that the pipeline is *correct*; choosing between two versions on it overfits (see `docs/challenge/EVALUATION.md`).
- Planning lives in GitHub issues as a wayfinder map (label `wayfinder:map`); use `/wayfinder` to work it.
